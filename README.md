# モーニングレポート自動配信 (Discord / 平日 09:00 JST)

保有銘柄（6740 / 7974 / 285A）＋日本半導体セクターの寄り付き前レポートを
毎営業日 Discord に自動投稿する。

## 設計思想：2層構造（これが精度の本体）

```
[層1] Python で決定論的にデータ収集・指標計算 → facts.json
        └ 株価・出来高・MACD/RSI/移動平均・S/R・類似チャート確率・信用倍率・ニュース
[層2] Claude は facts.json だけを根拠に文章化 → レポート
        └ 数値の創作を禁止。FACTSに無い項目は「現時点では確認できない」
[層3] 別モデルで数値のファクトチェック（audit）→ Discord に結果を併記
```

LLM に株価を直接聞くと必ず幻覚が出る。**数字は Python、文章は Claude** と役割を切るのが唯一の解。

## セットアップ手順

### 1. Discord Webhook を作る（5分）
1. 通知したいサーバー → チャンネル右の ⚙️「チャンネルの編集」
2. 「連携サービス」→「ウェブフック」→「新しいウェブフック」
3. 名前・アイコンを設定 →「ウェブフックURLをコピー」
   `https://discord.com/api/webhooks/xxxx/yyyy` の形式。**このURLは漏らすと誰でも投稿できる。**

### 2. API キーを取得
| 用途 | 取得先 | 費用 |
|---|---|---|
| Claude API | console.anthropic.com → API Keys | 従量。本構成で概算 1回 ¥40〜80／月 ¥1,000〜1,700 |
| J-Quants（信用倍率・空売り・投資部門別） | jpx-jquants.com | Free=12週遅延／**Light ¥1,650月**で前日分。Standard ¥3,300 |

J-Quants は登録後、メール/パスワードで `refresh_token` を取得（有効期限1週間 → 下記4で自動更新するか、Actionsで週次更新）。

### 3. GitHub リポジトリを作る
```bash
git init && git add . && git commit -m "init"
gh repo create morning-report --private --source=. --push
```
**必ず private。** Webhook URL と API キーは Secrets に入れる：

`Settings → Secrets and variables → Actions → New repository secret`
- `ANTHROPIC_API_KEY`
- `DISCORD_WEBHOOK_URL`
- `JQ_REFRESH_TOKEN`（無ければ該当項目は「確認できない」と出力される）

### 3.5 APIキー無しで動かす（推奨: まずこれ）

```powershell
python src/main.py --force --no-llm
```

`ANTHROPIC_API_KEY` が未設定でも自動でこのモードになる。
出力は `src/render.py` による**完全な決定論レポート**：米国市場・日経ギャップ・
保有株テクニカル全項目・セクター一覧・アナログ実測確率・ニュース見出し・データ欠損一覧。

| | 無LLM | LLM有り |
|---|---|---|
| 費用 | 0円 | Claude API従量 |
| 幻覚 | **原理的にゼロ** | 監査パスで検出 |
| ①②③④⑥⑦ | ✅ 全部出る | ✅ |
| ⑤市場心理 ⑧戦略 ★重要度 | ❌ 出ない | ✅ |

⑤⑧★は「数値」ではなく「判断」なので機械では作れない。逆に言えば、
**LLMが足しているのは判断だけで、事実は全部Pythonが作っている。**

### 4. ローカル動作確認
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...
export DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/...
python src/main.py --force      # 休場日でも強制実行
```
`out/facts_YYYYMMDD.json` を目で見て、値が入っているか・null が何かを確認する。
**ここで facts に無いものは、レポートにも絶対に出ない**（これが正しい挙動）。

### 5. スケジュール実行
`.github/workflows/morning.yml` を push すれば完了。cron は `35 23 * * 0-4`（UTC）= JST 月〜金 08:35 起動。

> ⚠️ GitHub Actions の cron は無料枠だと **15〜20分の遅延が常態**。9:00 厳守なら次のいずれかへ移行：
> - **Cloud Run Jobs + Cloud Scheduler**（GCP、月数十円、遅延ほぼゼロ）← 推奨
> - VPS（さくら/ConoHa 月¥500〜）で `crontab -e` → `50 8 * * 1-5 cd ~/morning-report && .venv/bin/python src/main.py`

東証休場日（土日・祝日・年末年始）は `jpholiday` で自動スキップ。

## 精度を上げる手順（効果が大きい順）

### ★★★★★ 1. 数値をLLMに書かせない（実装済）
`prompts/system.md` の絶対規則1〜2。FACTS に無いキーの数値は書かせない。
`analyst.audit()` が別モデルで全数値を突き合わせ、不一致があれば Embed が橙色になる。

### ★★★★★ 2. 「上昇確率」を勘ではなく実測頻度にする（実装済 / `src/analogs.py`）
元プロンプトの「推測禁止」と「上昇確率を出せ」は本来矛盾する。解決策：
- 直近60営業日の**正規化リターン系列**を検索キーに
- 2005年〜現在の全窓とユークリッド距離＋相関を計算
- 一致率上位20局面の**その後20日の実リターン**を集計
- → `empirical_up_prob_pct` / 中央値 / p10・p90

これで⑦（過去チャート比較）と③（上昇確率）が同時に、かつ検証可能な形で埋まる。
`analog.window` / `top_k` を config で調整し、`src/score.py` で効果を測る。

### ★★★★☆ 3. 取れないものを認める
以下は**無料データでは原理的に取れない**。捏造させるより「確認できない」と出す方が価値が高い：
| 項目 | 現実 | 課金すれば |
|---|---|---|
| 板状況・寄り付き気配 | 不可 | kabuステーションAPI（auカブコム、口座必須・無料）／立会情報ベンダー |
| リアルタイム出来高 | 20分遅延 | 同上 |
| 空売り比率（日次・銘柄別） | JPX公表は翌営業日 | J-Quants Light |
| X（旧Twitter）センチメント | API無料枠は事実上ゼロ | X API Basic $200/月 |
| Yahoo掲示板 | **スクレイピングは利用規約違反**。使わない | — |

→ SNS分析(⑤)を本気でやるなら **Reddit API（無料, PRAW）+ Stocktwits API + ニュース見出しの極性判定** が現実解。
ただし JDI/キオクシアは英語圏の言及がほぼ無く、母数不足で統計にならない点は先に受け入れる。

### ★★★★☆ 4. kabuステーションAPI で板を入れる
auカブコム証券の口座（無料）+ Windows常駐アプリ。`localhost:18080` に REST/WebSocket。
これを入れると③の「寄り付き気配・板状況」が本物になる。VPS ではなく自宅PC常駐が前提。

### ★★★★☆ 4.5 時差の罠（修正済 / v3）
米国指標と日本株の相関を**同日で取ってはいけない**。SOXのD終値はJST D+1朝5時に確定し、
日本株のD終値（JST D 15時）はそれより14時間早い。同日比較は無意味な相関を返す。
`collect.correlation(..., lag=1)` で必ず1日ずらす。合成データ検証: 真値0.8に対し
lag=0 → **-0.14** / lag=1 → **+0.89**。
**この種のバグは「それらしい数字」を返すので気づかれない。**

実測ログ（本番データ）:
| | 修正前(lag=0) | 修正後(lag=1) |
|---|---|---|
| 東京エレクトロン vs SOX | -0.00 | **0.50** |
| ルネサス vs SOX | (同様) | **0.53** |
| 米国勢 vs SOX (lag=0のまま) | 0.74〜0.85 | 変化なし |

さらに、判定を `code.endswith(".T")` で書いたせいで**韓国(.KS)を取りこぼした**。
SKハイニックス0.44 / サムスン0.40 に対し同業のマイクロンは0.83 —
韓国勢が日本株のレンジに収まっていたのが発覚の手がかりだった。
**判定基準はサフィックスではなくタイムゾーン**。`collect.market_lag()` に集約済み。

教訓: 指標を追加するたびに「その値は何時に確定するのか」を確認すること。

### ★★★☆☆ 5. フィードバックループを回す（実装済 / `src/score.py`）
```bash
python src/score.py 60   # 直近60レポートの判定を実績と突き合わせ
```
「買い増し」判定の5日後リターンが「様子見」を有意に上回らないなら、
⑧の判定ロジック（=プロンプト）が機能していない証拠。的中率を見ながら
`prompts/system.md` の⑧の根拠指定を絞る。**これをやらない限り精度は上がらない。**

### ★★★☆☆ 6. プロンプトを分割する
今は1コールで10セクション書かせている。品質が頭打ちなら
「①②マクロ」「③保有株」「④⑦セクター＋アナログ」「⑧戦略」の4コールに割り、
最後に統合コールを置く。トークン単価は上がるが各セクションの密度が上がる。

### ★★☆☆☆ 7. 前日レポートを文脈に入れる
`out/report_(前営業日).md` を FACTS に含めると「昨日の見立てからの変化」を書ける。
継続性が出て読み物として実用度が上がる。
