# 機関投資家の買い集め検出

`src/accumulation.py` → `out/accumulation.json` → ダッシュボードのパネル / Discordレポート。

## 1. 元になる考え方

> 機関投資家は運用する金額が大きいため、個人投資家のように一度で買えない。
> 何日も何週間もかけて少しずつ株を集める。そのため買われている銘柄には特徴が出る。

1. まず見るべきは出来高を伴った上昇。いつもの2倍3倍の出来高で株価が大きく上がる。
   これは普段より大きなお金が入った可能性がある。
2. 次に見るのは上がった後の値動き。普通なら大きく上がった後には利益確定の売りが出る。
   それでも株価があまり下がらず、高値付近を維持している。
   これは売られた株を誰かが買い続けている状態。
3. さらに、上がる日の出来高は多く、下がる日の出来高は少ない。
   この動きが続く銘柄は、大きな買いが入る一方で強く売られていない可能性がある。
4. 反対に注意したいのは、出来高が多いのに株価が上がらない銘柄。
   好決算で出来高が急増しても上ひげをつけて安値付近で終わる。
   これは大口が買っているのではなく、売っている可能性もある。
5. 大事なのは出来高が増えたことではない。増えた日に株価がどこで終わったか。
   高値付近で終われば買いが強い、安値付近で終われば売りが強い。この違いが重要。
6. 特に注目したいのが、決算後に大きく上がり、その後も窓を埋めず、
   狭い値幅で横ばいになる銘柄。機関投資家が少しずつ買い集めている可能性がある。
7. 結論として見るべきは「出来高が増えた株」ではなく「出来高が増えた後も売られない株」。

**この章は固定。** 数値化の都合で言い換えたり要約したりしない。
以下の実装はこの文章に対する暫定的な当てはめであって、この文章のほうが上位にある。

## 2. 数値化（閾値はすべて `config.yaml` の `accumulation:`）

| 記号 | 定義 | 既定値 |
|---|---|---|
| ① 出来高スパイク | `VolRatio = V / SMA(V,20)` | `>= 2.0` |
| ② 終値位置 | `CRP = (C - L) / (H - L)` | 高値引け `>= 0.7` / 安値引け `<= 0.3` |
| ③ U/D出来高比 | 直近50日 `Σ(上昇日の出来高) / Σ(下落日の出来高)` | `>= 1.5`（補助スコア） |
| ④ スパイク後の耐性 | N=10日、`P0`=スパイク日の終値、`R`=H−L | 下記3条件すべて |

④の内訳:
- **押し込み耐性** — 以降10日の最安値 `>= P0 - 0.5R`
- **窓を埋めない** — 以降10日の終値がスパイク日の始値を割らない
- **レンジ収縮** — 以降10日の平均 `(H-L)/C` < スパイク前20日平均の `0.7` 倍

判定:

| 判定 | 条件 |
|---|---|
| 候補 | ① かつ ②`CRP >= 0.7` |
| 集積の疑い | 候補の10日後に ④ をすべて満たす |
| 売り抜けの疑い | ① かつ ②`CRP <= 0.3` かつ 上ひげ `(H-C)/(H-L) >= 0.5` |

`SMA(V,20)` は**当日を含めない**（`vol_sma_exclude_today: true`）。含めるとスパイク日自身が
平均を押し上げ、「普段の2倍」という元の言葉より緩い判定になる。

## 3. 数値を出さない場合（このプロジェクトの最重要ルール）

推定・補完は一切しない。以下はすべて「値なし＋理由」で出す。

| 状況 | 出力 |
|---|---|
| `H == L` の日 | `CRP = null`。0.5 などで埋めない。候補にも逆アラートにもしない |
| 履歴 < `min_history_days`(300) | 値を出さず `判定に必要な日数が不足（N営業日 / 必要300営業日）` |
| スパイク後10日が未経過 | `候補（追跡中）` + `elapsed/needed`。**「④不成立」とは別物** |
| 決算日が取得できていない期間 | `earnings_spike = null` +理由。「通常スパイク」とは言わない |
| 株価取得に失敗 | `fetch_failed` に理由付きで積む。該当ゼロと区別する |
| 層2が未構築 | `status: ユニバース未構築`。空配列だけで「該当ゼロ」に見せない |

## 4. 決算スパイクの判別（考え方の6に対応）

**yfinance の `get_earnings_dates()` は使わない。** 2026-09-06 実測で、株価は 2026-09-04 まで
取れるのに決算日は約16か月前で止まっていた（7974 max=2025-05-08 / 8035 max=2025-04-30 /
6920 max=2025-04-28 / 285A max=2025-05-15 / NVDA max=2025-06-26）。
これを使うと直近1年のスパイクが全部「決算日不明」になる。

代わりに **TDnet（やのしんWEB-API）の決算短信の開示日時**を使う（`earnings.past_announcements()`）。
一次情報で、時刻まで持つ。同日実測で 7974 は 2009-10-29〜2026-08-06 の68件が取れた。

- 開示が **15:00以降** なら、その日の場は終わっている → 反応するのは**翌営業日**
- 反応日の前後 `window_bdays`(=1) 営業日以内のスパイクを「決算スパイク」とする
- APIの取得件数上限に当たった銘柄は `covers_from` を持ち回り、**それより古いスパイクは
  「決算ではない」と言わず「判別不可」**にする

キャッシュは `out/earnings_past.json`（既定168時間）。取得に失敗した銘柄はキャッシュに
残さない（失敗を成功として固定してしまうため）。

## 5. 2層構成

| | 層1 `core` | 層2 `universe` |
|---|---|---|
| 母集団 | `config.yaml` の `holdings + watch + sector` = 13銘柄 | 発掘用ユニバース |
| 主目的 | **売り抜けの疑い**（保有株の逆シグナル） | 集積の疑いの発掘 |
| 頻度 | 平日毎朝フル判定 | 週1回（土日）フル走査 |

層1は母集団が小さいので集積シグナルは**該当ゼロが常態**。画面はそれを「該当なし（判定は実行済み）」
と明示する。

層2の母集団は `accumulation.layers.universe.mode` で切り替える:

- **`nikkei225`** … Step2の規模テスト用。日経が配布する構成銘柄ウエートCSVから225銘柄。
  構成銘柄ページ(`indexes.nikkei.co.jp/nkave/index/component`)は Cloudflare のボット判定が
  入っていて中身が返らない（2026-09-06実測。200で返るのは challenge ページ）。CSVは直接取れる。
  **このCSVには日経の著作権表示があり再配布できない。** 銘柄一覧を公開物
  (`out/accumulation.json`・ダッシュボード) に出さないこと。
- **`jpx_filtered`** … Step3の本番ユニバース。下記。

### 層2ユニバースの構築（`jpx_filtered`）

```powershell
.\.venv\Scripts\python.exe src\universe_build.py   # 週1回。結果を out/universe_jpx_filtered.json に置く
```

絞る順番には理由がある。安い条件から先に掛けて、高い条件に渡す件数を減らす:

1. **区分・コード・規模区分** — ファイルだけで判定。ネットワーク不要
   - ETF/ETN・REIT等・PRO Market・外国株式・出資証券を除外
   - 5桁コードの優先株/社債型種類株を除外（実測7銘柄。いずれも「プライム（内国株式）」に
     入っているので市場区分では落ちない）
   - `TOPIX Core30` / `TOPIX Large70` を除外（時価総額の帯から明らかに外れる）
2. **履歴長・平均売買代金** — 一括取得した株価から計算。追加リクエストなし
   - 上場300営業日以上（④の計算に必要な履歴長）
   - 直近20日の平均売買代金 ≥ 3億円（`終値 × 出来高` の実測値。推定ではない）
3. **時価総額 300〜5,000億円** — 1銘柄1リクエスト（647ms実測）なので最後に置く
   - 大型すぎると機関の買いが出来高に痕跡を残さず、小型すぎると個人の単発注文で
     スパイクが立ちノイズになる
   - 取得できなかった銘柄は「帯の中かもしれないが確認できない」ので**通さない**

`yfinance` の `FastInfo` は属性が snake_case、dictキーが camelCase という二重の顔を持つ。
`fast_info.get("market_cap")` は例外を出さず `None` を返すので、これを使うと「全銘柄で
時価総額が取れない」状態が無言で起きる（実測で発生させた）。属性 `.market_cap` を使うこと。

取得に失敗したら「ユニバースを取得できていません」と出して層1のみで動作する。

### 銘柄コードは英数字4桁

`code.isdigit()` で判定してはいけない。東証の新しいコードには英字が入る
（**285A** キオクシア / **543A** ARCHION）。数字のみに絞ると、この2銘柄が理由も出さずに
母集団から消える（実測で発生させた）。`universe._is_tse_code()` を使う。

## 5-2. 規模の実測（Step2 / 2026-09-06）

日経225の225銘柄で計測:

| 工程 | 実測 |
|---|---|
| 銘柄リスト取得 | 0.24秒 |
| 株価一括取得（`yf.download`, 3y, chunk=40） | **6.1秒 / 失敗0件** |
| 指標計算（225銘柄） | 0.7秒 |
| 判定（225銘柄） | 0.2秒 |
| 決算日照会（TDnet 312ms × 141銘柄） | 約44秒 |
| **層1+層2 通し** | **52.7秒** |

1銘柄1リクエストの `fetch_history()` では数百銘柄でレート制限に当たるので、
`collect.fetch_ohlcv_batch()`（`yf.download` を chunk 単位）を使う。

決算日の照会は「**画面に出るスパイク**を持つ銘柄」だけに絞る。出来高が2倍でも終値位置が
中間(0.3〜0.7)の日は候補にも逆アラートにもならないので、決算かどうかを問う意味が無い。
225銘柄で 174 → 141 に減る。

## 6. 実行頻度と候補フラグの永続化

数百銘柄を毎朝 yfinance で叩くと失敗しやすいので二段構えにする。

- **週1回（土日）**: 層2ユニバース全体をフル走査し、候補フラグを記録
- **平日毎朝**: 層1の全銘柄 ＋ 層2で候補フラグが立っている銘柄のみを追跡

候補フラグは `out/accumulation_state.json` に永続化する。④は10日間の追跡なので、
平日の追跡対象は常に数十件以下に収まる。`candidate_keep_days`(40営業日) を過ぎた候補は落とす。

## 7. 検証

```powershell
.\.venv\Scripts\python.exe src\accumulation_backtest.py --horizon 20 --json out\accumulation_backtest.json
```

シグナル確定日（集積はスパイク+10日、売り抜けはスパイク当日）の終値を起点に、
`horizon` 営業日後の騰落率を集計する。スパイク日の終値を起点にすると④の判定に使った
10日ぶんの値動きを事前に知っていたことになるので、そうしない。
履歴が300営業日に満たない銘柄は自動的に除外し、除外した旨をログに出す。

同じ銘柄・同じ期間の全営業日を起点にしたベースラインを必ず併記する。
これが無いと勝率55%が高いのか低いのか判断できない。

### 2026-09-06 の測定結果（層1の13銘柄・全履歴・horizon=20営業日）

| | n | 勝率 | 平均騰落率 |
|---|---|---|---|
| ベースライン（全営業日起点） | 58,499 | 52.85% | +1.98% |
| **集積の疑い（④3条件すべて＝仕様どおり）** | **17** | 52.94% | +0.59% |
| 参考: ④の押し込み耐性＋窓維持のみ（レンジ収縮を外す） | 330 | 57.88% | +3.74% |
| 参考: レンジ収縮の倍率を 1.0 に緩める | 113 | 55.75% | +2.07% |
| 参考: レンジ収縮の倍率を 1.2 に緩める | 191 | 56.54% | +2.30% |
| 売り抜けの疑い | 937 | 50.37% | +1.24% |

**レンジ収縮条件が実質的に全部を落としている。** 仕様どおりの3条件では22年間で17件しか
成立せず、しかも2018-05を最後に一度も出ていない。ベースラインに対する優位も無い（n=17では
そもそも何も言えない）。一方で押し込み耐性＋窓維持の2条件だけなら n=330 で勝率+5.0pt・
平均+1.76pt とベースラインを上回る。倍率を1.0や1.2に緩めた中間よりも、外したほうが良い。

ただし **閾値はまだ変更していない**。理由:
- レンジ収縮は考え方の6（「狭い値幅で横ばい」）そのものであり、勝手に外してよい条件ではない
- 13銘柄は半導体・電機に偏っており、シグナルも時期が固まっている。n=330も独立ではない
- Step3で層2（600〜900銘柄）を作ってから測り直すのが順序

判断は保留。層2を作った後に再測定して決める。
